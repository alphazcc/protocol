# 协议规范

本文定义 `proto` 1.x 的线上帧格式、字段编码、校验算法与一致性要求。文中 `MUST`、`MUST NOT`、`SHOULD` 和 `MAY` 按 RFC 2119 解释。线上格式以本文为准，库实现必须符合本文。

## 1. 术语与记法

- **字节**：8 位无符号整数。
- **十六进制**：`ED` 表示单个字节；多字节数值按传输顺序书写。
- **大端序**：高字节先传输。
- `n`：数据长度字段的值，取值范围为 `0..96`。
- **帧总长**：`14 + n`，即固定开销 14 字节加数据区长度。
- **`[a, b)`**：下标从 `a` 开始、到 `b` 之前结束的字节区间。

## 2. 帧结构

| 序号 | 字段 | 偏移 | 长度 | 取值与编码 |
| :--: | :-- | :--: | :--: | :-- |
| 1 | 帧头 | 0 | 4 | 固定为 `ED B9 55 AA` |
| 2 | 设备类型 | 4 | 1 | 任意字节，语义由应用层定义 |
| 3 | 命令 | 5 | 1 | 任意字节，语义由应用层定义 |
| 4 | 功能码 | 6 | 2 | 大端序 `uint16_t` |
| 5 | 数据长度 | 8 | 2 | 大端序 `uint16_t`，值为 `n`，必须 `n <= 96` |
| 6 | 数据 | 10 | `n` | 不透明字节序列 |
| 7 | CRC | `10 + n` | 2 | 大端序 `uint16_t`，覆盖 `[0, 10 + n)` |
| 8 | 帧尾 | `12 + n` | 2 | 固定为 `5A A5` |

```text
偏移:  0        4    5    6       8        10           10+n     12+n
字段:  HEAD     T    C    CODE    LEN      DATA         CRC      TAIL
长度:  4        1    1    2       2        n            2        2
```

帧最小长度为 14 字节（`n = 0`），最大长度为 110 字节（`n = 96`）。

## 3. 编码规则

1. 帧头与帧尾 MUST 为第 2 节表中规定的固定字节序列。
2. 设备类型与命令是应用层定义的不透明字节，本协议不解释其含义。
3. 功能码、数据长度与 CRC MUST 采用大端序传输。
4. 数据区是长度定界的字节序列，其中出现帧头或帧尾字节序列时 MUST NOT 进行转义，也 MUST NOT 被解释为分帧边界。
5. 数据长度超过 96 的帧不符合本协议，接收端 MUST 拒绝。

## 4. CRC16/Modbus

CRC 覆盖区间为 `[0, 10 + n)`，即从帧头首字节到数据区末字节，不含 CRC 字段本身与帧尾。

| 参数 | 标准参数目录记法 | 实现采用的反射等价记法 |
| :-- | :-- | :-- |
| 多项式 | `0x8005` | `0xA001` |
| 初值 | `0xFFFF` | `0xFFFF` |
| 输入反射 `refin` | `true` | 不适用：字节直接异或到 CRC 低 8 位 |
| 输出反射 `refout` | `true` | 不适用：结果无需再次反转 |
| 异或输出 `xorout` | `0x0000` | `0x0000` |

实现采用反射等价形式：以 `0xA001` 为多项式，将每个输入字节直接异或到 CRC 低 8 位，随后按位右移并在最低位为 1 时异或多项式。`MUST NOT` 在采用反射多项式的同时再次反转输入字节，否则会造成重复反射并产生错误结果。

标准自检值：对字符串 `"123456789"`，CRC 为 `0x4B37`。逐位实现与 256 项查表实现 MUST 产生相同结果。

## 5. 一致性向量

### 5.1 空数据帧

```text
ED B9 55 AA 00 00 00 00 00 00 35 75 5A A5
```

该帧声明 `n = 0`，待校验字节为前 10 字节，CRC 为 `0x3575`。

### 5.2 含数据帧

```text
待校验字节（帧头至数据区末）:
    ED B9 55 AA 01 02 AB CD 00 08 12 34 56 78 AB CD EF 5A
CRC : 1447
完整帧（14 + 8 = 22 字节）:
    ED B9 55 AA 01 02 AB CD 00 08 12 34 56 78 AB CD EF 5A 14 47 5A A5
```

解析结果：

| 字段 | 值 |
| :-- | :-- |
| 设备类型 | `01` |
| 命令 | `02` |
| 功能码 | `ABCD` |
| 数据长度 | `8` |
| 数据 | `12 34 56 78 AB CD EF 5A` |

该向量的数据区以 `5A` 结束，与帧尾首字节相同；接收端 MUST 依据长度字段界定数据区，而非依据字节值推断边界。

## 6. 分帧与一致性规则

1. 候选帧起点 MUST 与 4 字节帧头完全匹配。
2. 从候选起点起可用字节数小于 10 时，长度字段不可读，该候选 MUST 判为未收全，`span.size` MUST 为 0。
3. 声明的 `n > 96` 时，该候选 MUST 被拒绝，扫描 MUST 继续寻找后续候选。
4. 从候选起点起可用字节数小于 `14 + n` 时，该候选 MUST 判为未收全，`span.size` MUST 为 `14 + n`。
5. 可用字节数达到或超过 `14 + n` 时，MUST 按声明的 `n` 校验该候选：长度一致性、帧尾、CRC 全部通过才被接受；任一项失败则拒绝该候选并继续扫描。
6. `proto_decode()` MUST 要求输入长度恰好为 `14 + n`；短于或长于该值均 MUST NOT 接受。
7. 若更靠后存在通过全部校验的完整帧，该完整帧 MUST 优先于更早的未收全或已拒绝候选被返回。
8. 数据区中出现的帧头或帧尾字节序列 MUST NOT 具有特殊语义。
9. `proto_find_bounded()` 的 `window` 仅限制候选起点下标，使其落在 `[0, min(window, size) - 4]`；帧体可延伸到窗口之外，但全部字节 MUST 在 `size` 范围内。`window < 4` 时 MUST 返回“无有效帧”。调用方 MUST 按最坏噪声前缀长度设定窗口。

## 7. 错误检测与处置

- `proto_decode()` 返回具体状态码，用于区分帧头、长度、帧尾与 CRC 失败。
- `proto_find()` 与 `proto_find_bounded()` 将大多数校验失败归并为 `PROTO_E_NOFRAME`，仅在已识别帧头但未收全时返回 `PROTO_E_INCOMPLETE`。
- 状态码数值与文本定义见 [状态码](ERROR_CODES.md)。
- CRC 校验失败或帧尾不匹配 SHOULD 记录为链路误码；持续失败 SHOULD 触发对端实现或链路质量检查。

## 8. 一致性验证

- `tests/test_crc16.c` 覆盖协议一致性向量。
- `tests/test_crc16_diff.c` 在 `n = 0..200` 上将当前库实现与独立的参考逐位实现、参考查表实现进行三方比对。
- 两种库 CRC 实现分别由 CI 的默认配置与查表配置运行同一差分测试，从而覆盖二者的等价性。
- CI 以默认、查表、`memchr` 预筛、双开四种算法配置运行六组测试，并覆盖 GCC、MSVC 与 MinGW。

## 9. 安全考量

- CRC16 仅用于检测随机传输错误，不具备抗恶意篡改能力；需要认证时 MUST 在更上层增加消息认证码。
- 库不限制累计接收字节数；调用方 MUST 约束接收缓冲区容量，并对持续未收全设置超时。
- 单帧最坏分帧扫描复杂度为 `O(缓冲区长度 × 帧最大长度)`；实时场景 SHOULD 使用 `proto_find_bounded()`。候选数量与窗口长度成正比，每个完整候选的 CRC 处理另需 `O(96 × 8)`，两部分最坏时间 MUST 分别估算。
- 有界窗口只约束候选帧头起点；若有效帧前的噪声长度超过窗口，该帧不会被发现。
